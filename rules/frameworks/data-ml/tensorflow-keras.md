# TensorFlow / Keras

1. **Check versions first - the ecosystem forked repeatedly:** TF1 vs TF2 (eager), standalone Keras 3 (multi-backend: TF/JAX/PyTorch) vs `tf.keras`; APIs and imports differ. Read the lockfile and existing imports before writing from memory.
2. **Keras API tiers by need:** `Sequential` for straight stacks, functional API for DAGs/multi-input-output (the workhorse), model subclassing only when control flow demands it - subclassed models lose serialization and summary ergonomics; don't pay that for nothing.
3. **Loss/activation contracts:** `from_logits=True` with no final activation (preferred, numerically stable) or softmax/sigmoid with `from_logits=False` - mixing them trains wrong silently. Sparse vs one-hot losses matched to label format.
4. **`model.compile` is part of the experiment record:** optimizer (with explicit LR), loss, and metrics declared deliberately; LR schedules via `keras.optimizers.schedules` or callbacks; class weights/sample weights for imbalance stated, not forgotten.
5. **`tf.data` is the input pipeline:** `.map(parse, num_parallel_calls=AUTOTUNE).cache().shuffle(N).batch(B).prefetch(AUTOTUNE)` - order matters (shuffle before batch; cache before heavy augmentation only if augmentation should vary per epoch... it should, so cache before it). Python-loop feeding starves accelerators.
6. **`@tf.function` rules (graph mode):** no Python side effects relied on per-call, watch retracing (stable input signatures, `input_signature=` where shapes vary), `tf.print` not `print` inside; debug eagerly first (`run_eagerly=True`), then compile.
7. **Callbacks over hand-rolled loop logic:** `ModelCheckpoint` (save best, `save_weights_only` decision explicit), `EarlyStopping` (with `restore_best_weights=True`), `ReduceLROnPlateau`, TensorBoard - the standard quartet before custom training loops. Custom loops (`GradientTape`) only when `fit` genuinely can't express it, and then: correct `training=` flags and `trainable_variables` only.
8. **Train/eval mode flows through `training=`:** batchnorm/dropout keyed off it in functional/subclassed calls - `model(x, training=False)` for inference; forgetting it corrupts evaluation.
9. **Reproducibility:** `keras.utils.set_random_seed(n)` (seeds Python/NumPy/backend), `tf.config.experimental.enable_op_determinism()` when full determinism is worth the slowdown; dataset shuffles seeded.
10. **Save in the modern format:** `.keras` (Keras 3) / SavedModel for serving - with custom objects registered (`@keras.saving.register_keras_serializable`); never pickle models. Loading anything untrusted is code execution - same rule as everywhere.
11. **Memory and devices:** GPU memory growth enabled where sharing (`set_memory_growth`), mixed precision (`mixed_float16` policy) with loss scaling for big models, `model.summary()` sanity-checked (param counts catch wiring bugs early).
12. **Overfit-one-batch before scaling** - same rule as PyTorch: prove the wiring can memorize, then train for real; and keep runs reproducible from config + seed + code version in the project's tracker.
