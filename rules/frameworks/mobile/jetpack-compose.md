# Jetpack Compose

1. **Kotlin rules apply first** (see kotlin.md) - null discipline, coroutines/Flow, sealed state modeling. Compose adds recomposition, state hoisting, and Android lifecycles.
2. **Composables are pure functions of state:** no side effects in composition - no network, no navigation calls, no mutating shared objects mid-composition. Effects go through the effect APIs; everything else derives from parameters.
3. **State hoisting is the default shape:** stateless composables taking `value` + `onValueChange`, state owned by the caller or ViewModel. `remember { mutableStateOf() }` for genuinely view-local state; `rememberSaveable` when it must survive rotation/process death.
4. **UI state comes from the ViewModel as a single `StateFlow<UiState>`** (sealed interface / data class), collected with `collectAsStateWithLifecycle()` - not multiple loose LiveDatas, not GlobalScope, not state mutated from random layers. Events up via lambdas.
5. **Effect APIs by contract:** `LaunchedEffect(key)` for suspend work tied to composition (keys chosen honestly - wrong keys = stale or restarting effects), `DisposableEffect` for subscribe/unsubscribe pairs, `SideEffect` for publishing to non-Compose code, `rememberCoroutineScope` for event-handler-launched work. `snapshotFlow` to observe Compose state as a Flow.
6. **Recomposition is frequent - make it cheap and correct:** don't allocate/compute heavily in composable bodies (`remember` derivations, `derivedStateOf` for high-frequency reductions like scroll position); stable parameter types (immutable data classes, persistent lists per project convention); lambdas that capture stable references.
7. **Lists are `LazyColumn`/`LazyRow`/lazy grids with stable `key = { it.id }`** - never `Column` + `forEach` for unbounded content; `contentType` for mixed rows; don't nest same-direction scrollables.
8. **Layout idiomatically:** Modifier order matters and is meaningful (padding-then-background != background-then-padding) - read chains carefully; `Modifier` is the first optional parameter of every public composable; slot APIs (`content: @Composable () -> Unit`) for flexible components; constraints understood before reaching for `Layout`/`BoxWithConstraints`.
9. **Theming through MaterialTheme (or the house design system):** colors/typography/shapes from the theme, not hardcoded - dark theme and dynamic color come free only if you stay inside it.
10. **Navigation via the project's solution (Navigation-Compose, type-safe routes where adopted):** navigate in callbacks/effects - never during composition; arguments are IDs/primitives, not objects.
11. **Android still exists:** lifecycle-aware collection (`collectAsStateWithLifecycle`, `repeatOnLifecycle` in non-Compose collectors), configuration changes handled by state design not `android:configChanges`, permissions and system bars through the accompaniment APIs the project uses.
12. **Accessibility and testing share the semantics tree:** `contentDescription` on meaningful icons/images (null for decorative), `Modifier.semantics` merging for composite controls, minimum touch targets - then test with `createComposeRule`, `onNodeWithText/Tag`, and screenshot tests where the team runs them.
