# Rust Web Services - Axum / Actix Web

1. **Rust rules apply first** (see rust.md) - no `unwrap()` on request paths, errors as values, no locks held across `.await`. Check which framework and version (`Cargo.toml`): Axum's extractor/state APIs shifted across 0.6->0.7->0.8; Actix has its own actor-flavored idioms.
2. **A panic in a handler is a 500 and a stack unwind - never panic on input.** Every fallible step returns `Result`; the error type implements `IntoResponse` (Axum) / `ResponseError` (Actix) mapping domain errors to status codes with a consistent JSON error body. One app-wide error enum (`thiserror`) beats per-handler ad-hoc responses.
3. **State via the framework's mechanism:** Axum `State<Arc<AppState>>` (cheap-clone handles: pools, clients, config), Actix `web::Data<T>`. No `static` globals/`lazy_static` mutable state; anything mutable inside state uses the async-aware sync primitives (`tokio::sync`) with short critical sections.
4. **Extractors are the validation boundary:** typed `Json<CreateUser>`/`Path`/`Query` structs with serde (`deny_unknown_fields` where the contract is strict), plus a validation pass (validator crate or manual) before logic. Extractor rejections should flow through the same error shape - customize the rejection handling.
5. **Don't block the runtime:** CPU-heavy or sync-IO work goes through `spawn_blocking` (or rayon for compute); one synchronous bcrypt/zip/image-resize call inline stalls a worker thread's tasks. Async-native libraries (sqlx, reqwest) throughout.
6. **Spawned tasks are owned:** `tokio::spawn` results tracked (JoinHandle/JoinSet) or deliberately detached with a comment; background work gets cancellation via `CancellationToken`/watch channels and participates in graceful shutdown (`with_graceful_shutdown`, drain, close pools).
7. **Middleware via tower layers (Axum) / Actix middleware:** tracing (`tower-http` TraceLayer with request IDs), timeouts, body limits, compression, CORS as explicit allowlist - composed once, visibly. Timeouts on the server AND every outbound client (`reqwest` default has none).
8. **Database with sqlx/diesel/sea-orm per the project:** compile-checked queries where sqlx offers them, pool sized deliberately, transactions via the API (commit consumed, rollback on drop understood), migrations under version control (`sqlx migrate`/`diesel migration` - reviewed like code).
9. **Auth as an extractor/middleware:** a `CurrentUser` extractor that validates the token once, handlers taking it as a parameter - and resource ownership still checked against the loaded row. Secrets from env into typed config at boot (fail fast), never hardcoded.
10. **Observability via `tracing`, not `println!`:** `#[instrument]` on handlers/services (skip sensitive fields), structured fields, spans across await points - this is also how you debug async at all.
11. **Tests:** handler/router tests with `tower::ServiceExt::oneshot` (Axum) or `actix_web::test` harness, real router wiring, Testcontainers for the DB; unit-test domain logic as plain functions - keep it out of handlers so that's easy.
