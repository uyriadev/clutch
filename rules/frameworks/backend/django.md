# Django

## Work with the framework, not around it

1. **Fat models / focused services, thin views, dumb templates.** Business logic lives in models, managers, or a service layer (match the house pattern) - never in templates, rarely sprawling in views.
2. **Use what Django ships before adding anything:** auth, sessions, admin, forms, pagination, signals (sparingly), cache framework, `LoginRequiredMixin`/decorators. Reimplementing a built-in is a review rejection.
3. **The ORM is the API to the database:** raw SQL via `.raw()`/`connection` only with a reason, and parameterized when used.

## ORM - where Django performance lives and dies

4. **Kill N+1s by default:** `select_related` (FK/one-to-one), `prefetch_related` (M2M/reverse FK) on any queryset whose related objects get touched. Assume list views need them; verify with `django-debug-toolbar` or query logging.
5. **QuerySets are lazy and cached - exploit both:** build filters incrementally (no cost until evaluation), but don't re-evaluate the same queryset in a loop. `exists()` not `count()` for presence, `count()` not `len()` for counting, `values`/`values_list`/`only` when you don't need model instances, `iterator()` for huge scans.
6. **Push work into the database:** `filter`/`aggregate`/`annotate`/`F()` expressions over Python loops; `update()`/`bulk_create`/`bulk_update` over save-per-row (knowing they skip signals and `save()` - say so when it matters). `F()` for read-modify-write (`views = F('views') + 1`) to avoid races.
7. **Migrations are code review material:** generated by `makemigrations`, inspected before commit, reversible where feasible; data migrations separate from schema; never edit an applied migration. On big tables, know which operations lock.

## Views, forms, security

8. **Validation belongs to Forms/DRF Serializers - never hand-parse `request.POST`/`request.body`.** Model constraints (`unique`, `CheckConstraint`) back up form validation at the DB layer.
9. **Django's security defaults are opt-out - don't opt out:** CSRF middleware on (exempt only signed/webhook endpoints, with justification), template autoescaping intact (`|safe`/`mark_safe` require sanitized input), `get_object_or_404` scoped to the requesting user (`owner=request.user`) - the unscoped version is an IDOR.
10. **Authorization is explicit per view:** login required + object-level permission checks. Querysets filtered by ownership are the cleanest enforcement.
11. **CBVs vs FBVs: match the codebase;** either way keep per-request work in the view, not module scope. `settings` via `django.conf`, secrets via env (django-environ style), `DEBUG=False` semantics respected (ALLOWED_HOSTS, static files story).

## Async and jobs

12. **Slow work goes to Celery/RQ/django-tasks, not the request cycle.** Pass IDs to tasks, not model instances (they serialize stale). Make tasks idempotent - queues redeliver.
13. **Async views only with an async-capable stack end-to-end** (ASGI, async ORM calls `aget`/`afilter`); mixing sync ORM into async views needs `sync_to_async` and a reason.
14. **Tests: pytest-django (or the house runner), factories over fixtures, `assertNumQueries` on list endpoints** to lock N+1 fixes in place.
