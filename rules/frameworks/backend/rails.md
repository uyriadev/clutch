# Ruby on Rails

1. **The Rails Way wins ties:** convention over configuration - RESTful resource routes (7 actions; more = new controller or nested resource), naming conventions, generators. Code that fights Rails reads as wrong to every Rails developer.
2. **Skinny controllers; models and POROs carry the logic.** Controllers: authenticate -> authorize -> strong params -> call one domain method -> respond. When models bloat, extract service objects/concerns per the house pattern - not logic into views or helpers.
3. **Strong parameters always:** `params.require(:post).permit(...)` (or `params.expect` in 8+) - no `permit!`, no passing raw params to `create`/`update`.
4. **N+1s are the Rails performance tax - pay it up front:** `includes`/`preload`/`eager_load` on every association a view iterates; `strict_loading` (model-level or `config.active_record.strict_loading_by_default` in dev) to make violations raise; `counter_cache` or `size`-over-`count` awareness; `find_each`/`in_batches` for large scans.
5. **Validations in the model AND constraints in the database:** `validates` for UX, `null: false`/unique indexes/foreign keys for truth - `validates_uniqueness_of` without a unique index is a race condition, not a guarantee.
6. **Migrations: generated, reviewed, reversible (`change` with care, `up/down` when not);** never edit applied migrations; `schema.rb`/`structure.sql` committed. On big tables know what locks (adding NOT NULL, indexes -> `algorithm: :concurrently` on Postgres, `strong_migrations` gem if present).
7. **Authorization is explicit per action:** Pundit/CanCanCan policies (or house equivalent) + scoping queries to `current_user` (`current_user.posts.find(params[:id])` - the global `Post.find` is the IDOR). `before_action :authenticate_*` as the outer gate.
8. **Background jobs for anything slow** (ActiveJob over raw Sidekiq API in app code): pass IDs (GlobalID handles AR objects - but jobs must tolerate deleted records), idempotent `perform`, retries/discard declared, mailers `deliver_later`.
9. **Rails' security defaults stay on:** CSRF protection (`protect_from_forgery` - API-only tokens instead), ERB auto-escaping (`raw`/`html_safe` only on sanitized content), signed/encrypted cookies via credentials, `Rails.application.credentials` or env for secrets - never `config/*.yml` with keys committed.
10. **Use the framework's breadth before adding gems:** ActiveStorage (files), ActionCable/Turbo (real-time), ActiveSupport (`present?`, `blank?`, durations), enum, `delegated_type`, Turbo/Stimulus for Hotwire-era frontends - match what the app already uses.
11. **Callbacks with restraint:** lifecycle callbacks that touch other models or external services are hidden control flow - prefer explicit service objects; `after_commit` (not `after_save`) for anything external like jobs and mails.
12. **Tests per house framework (RSpec or minitest):** request specs over controller specs, factories (FactoryBot) with minimal traits, system tests for critical flows, `assert_enqueued_jobs`/mail assertions via the built-in test adapters.
