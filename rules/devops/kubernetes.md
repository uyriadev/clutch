# Kubernetes

1. **Everything is declarative YAML in version control** - no `kubectl edit`/imperative mutations on shared clusters (they evaporate on next apply and desync the repo). Kustomize/Helm per the project; GitOps flow respected where it exists.
2. **Requests and limits on every container:** memory request=limit (avoid overcommit-driven OOMKills of innocents), CPU request set / limit as a policy decision (throttling awareness). No resources block means the scheduler is guessing and the node is at risk.
3. **All three probes, honestly:** liveness (restart if truly dead - keep it dumb; a DB-checking liveness probe restart-loops the whole fleet during a DB blip), readiness (traffic gate - this one checks dependencies), startup (slow-boot protection). Wrong probes cause outages by themselves.
4. **Graceful shutdown choreography:** handle SIGTERM (stop accepting, drain), `terminationGracePeriodSeconds` sized to real drain time, preStop sleep for load-balancer deregistration lag - otherwise every deploy drops requests.
5. **Availability is designed, not defaulted:** 2+ replicas for anything serving traffic, `PodDisruptionBudget` (or node maintenance kills your quorum), pod anti-affinity/topology spread across nodes/zones, and a tested `RollingUpdate` strategy (`maxUnavailable`/`maxSurge` chosen, not inherited).
6. **Security context as the floor:** `runAsNonRoot: true`, `allowPrivilegeEscalation: false`, `readOnlyRootFilesystem` where possible, capabilities dropped (`drop: [ALL]`), no privileged pods outside system namespaces; images pinned by tag+digest for prod.
7. **Secrets are not ConfigMaps:** Secrets (with encryption at rest / external-secrets operator + a real secret manager per infra), mounted or env-injected - never in image, never in the manifest committed plaintext (sealed-secrets/SOPS if secrets touch git). ConfigMaps for genuinely non-sensitive config; both trigger no automatic pod reload - plan rollout on change (checksum annotations).
8. **RBAC least-privilege:** dedicated ServiceAccounts per workload (never default with permissions), Roles scoped to namespace and verbs actually used, no `cluster-admin` bindings for applications, `automountServiceAccountToken: false` when the pod doesn't talk to the API.
9. **Namespaces are the unit of blast radius:** per team/env, with ResourceQuotas and LimitRanges; NetworkPolicies default-deny where the CNI supports it - a flat any-to-any pod network is the default and rarely the intent.
10. **The right controller for the job:** Deployment for stateless, StatefulSet only for genuinely stateful identity/storage needs, Job/CronJob for batch (with `backoffLimit`, `activeDeadlineSeconds`, concurrency policy - a hung CronJob without deadlines piles up forever), DaemonSet for per-node agents.
11. **Debug with the evidence chain:** `kubectl describe` (events!) -> `logs --previous` (the crash before the restart) -> `get events --sort-by` -> exec/ephemeral debug containers last. CrashLoopBackOff is a symptom; the previous-container log is the cause.
12. **Version and API hygiene:** manifests target the cluster's actual version (check deprecated API removals before upgrades - `kubectl-convert`/pluto), labels/selectors consistent (`app.kubernetes.io/*` conventions), and every change applies cleanly from the repo (`kubectl diff` before apply).
