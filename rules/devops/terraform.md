# Terraform / OpenTofu

1. **State is the crown jewels:** remote backend (S3+locking/Terraform Cloud/equivalent) always - never local state for shared infra, never state files in git (they contain secrets in plaintext), locking enabled, and state surgery (`state mv/rm`, imports) treated as production changes with backups first.
2. **`plan` is the review artifact:** every change reviewed as a plan output before apply (CI posts it to the PR); an apply whose plan wasn't read is a production change nobody approved. `-target` is an incident tool, not a workflow; unexplained diffs (drift) get investigated, not applied over.
3. **Destructive operations get flagged loudly:** anything showing `destroy`/`replace` on stateful resources (databases, buckets, volumes) stops for explicit confirmation; `lifecycle { prevent_destroy = true }` on the irreplaceable; deletion protection at the provider level too - Terraform will cheerfully delete a database because a name changed.
4. **No secrets in `.tf` or `.tfvars` committed to git:** secret manager references (data sources), env-provided variables (`TF_VAR_`), and `sensitive = true` on variables/outputs (knowing it masks display, not state - hence rule 1). Provider credentials from the environment/OIDC, never hardcoded.
5. **Modules for repeated shape, not for everything:** root configs per environment composing versioned modules (pinned: `?ref=v1.2.0`, registry `~>` constraints); a module wrapping one resource with all its arguments re-exposed is indirection tax. Environments separate by state (workspaces or - sturdier - directory-per-env), never by if-else on a variable inside one state.
6. **Pin everything:** `required_version`, provider versions (`~>` constraints + lockfile `.terraform.lock.hcl` committed), module refs - an unpinned provider upgrade is a surprise refactor of production.
7. **Names and structure by convention:** resource names describe role not repetition (`aws_instance.web` not `aws_instance.web_instance`), `variables.tf`/`outputs.tf`/`main.tf` layout, every variable typed with `description` (+ `validation` blocks for constraints), outputs documented - the config is the documentation.
8. **`for_each` over `count` for collections** (keyed by stable identifiers - count-indexed resources reshuffle and recreate on reorder); locals for derived values; data sources over hardcoded IDs/ARNs; no magic strings that differ per environment outside variables.
9. **Keep it declarative:** minimal provisioners (`local-exec`/`remote-exec` are the escape hatch of last resort - cloud-init/config management/operators do that job), no logic pretzels - if the HCL needs three levels of nested ternaries, restructure the inputs.
10. **Hygiene gates in CI:** `fmt -check`, `validate`, lint (tflint), security scan (trivy/checkov), plan on PR, apply only from the pipeline on the main branch - humans running apply from laptops is drift and mystery in one move.
11. **Blast-radius discipline:** state per domain/layer (network / data / app) so a bad apply can't take everything; cross-state references via remote state data sources or explicit outputs; small applies over monolith states with 30-minute plans.
