# PostgreSQL

1. **SQL rules apply first** (see ../languages/sql.md) - parameterization, NULL logic, transactions. These are the Postgres-specific ones.
2. **Types Postgres does better - use them:** `timestamptz` (never bare `timestamp` for moments in time), `text` (no arbitrary `varchar(255)` cargo-culting - constrain with CHECK when there's a real limit), `numeric` for money, `uuid`, `jsonb` (not `json`), arrays and enums where they model the domain (enums: know that adding values is easy, removing isn't).
3. **`jsonb` is for genuinely schemaless data, not schema avoidance:** columns you filter/join on belong as columns; index jsonb paths you query (GIN, expression indexes); don't build an EAV store inside a relational database that already does relations.
4. **Index deliberately:** B-tree default; GIN for jsonb/arrays/full-text; partial indexes for hot subsets (`WHERE status = 'active'`); expression indexes to match query shape (`lower(email)`); covering (`INCLUDE`) for index-only scans. Every index verified with `EXPLAIN (ANALYZE, BUFFERS)` on realistic data - Postgres won't use what doesn't fit the query.
5. **Migrations respect locks:** `CREATE INDEX CONCURRENTLY` on live tables (outside a transaction); adding a column with a volatile default rewrites the table on old versions - check the project's PG version; `NOT NULL` on big tables via `NOT VALID` constraint + `VALIDATE` in steps. Long `ALTER TABLE` locks are outages.
6. **MVCC has consequences:** long-running transactions block vacuum and bloat everything - keep transactions short; count queries scan (cache counts where hot); autovacuum is your friend - don't disable it, tune it (per-table settings for high-churn tables).
7. **Upserts natively:** `INSERT ... ON CONFLICT (key) DO UPDATE/NOTHING` - not select-then-insert races. `RETURNING` to get generated values without a second query. CTEs for multi-step atomic writes.
8. **Row locking chosen precisely:** `SELECT ... FOR UPDATE` for read-modify-write; `FOR UPDATE SKIP LOCKED` for job queues (the canonical pattern); advisory locks for application-level mutexes - not table locks, not serializable-everything.
9. **Full-text and fuzzy search built-in before adding infrastructure:** `tsvector`/`tsquery` + GIN, `pg_trgm` for fuzzy/LIKE acceleration - reach for Elasticsearch only past what these do.
10. **Connection pooling is mandatory at scale:** Postgres connections are processes - hundreds are expensive. PgBouncer/pgcat or the framework pool, sized deliberately; transaction-mode pooling breaks session state (prepared statements, `SET`) - know which mode.
11. **Observability from the catalog:** `pg_stat_statements` for slow-query truth, `pg_stat_user_indexes` for unused indexes, `pg_locks` for contention - check these before guessing.
12. **Postgres version matters:** major versions add real features (MERGE 15, logical replication improvements, JSON syntax 17+) and change planner behavior - verify against the deployed version, not memory.
