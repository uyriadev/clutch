# pytest

1. **Principles first** (see testing-principles.md); these are the pytest mechanics. Plain `assert` statements (pytest rewrites them for rich diffs) - no `unittest`-style `self.assertEqual` in pytest-native code; match the project's existing style if it's unittest-based.
2. **Fixtures are the dependency-injection system - use them properly:** request by parameter name, compose fixtures from fixtures, `yield` fixtures for setup/teardown pairs (teardown after the yield runs even on failure). Scope deliberately: `function` default; `session`/`module` only for expensive immutable resources - a session-scoped fixture with mutable state is cross-test contamination.
3. **`conftest.py` is the sanctioned sharing mechanism:** shared fixtures live there (discovered without imports, nearest-directory-wins); don't import fixtures across test modules by hand. But don't let root conftest become a 500-line junk drawer - scope conftests to the directories that need them.
4. **`pytest.raises` with specificity:** `with pytest.raises(ValueError, match=r"invalid tier")` - asserting the type alone lets the wrong error pass; asserting outside a context manager doesn't work. `pytest.warns` for warning contracts.
5. **Parametrize instead of copy-pasting:** `@pytest.mark.parametrize` with `ids=` for readable failure output; stack parametrize decorators for cartesian cases; `pytest.param(..., marks=pytest.mark.xfail)` for known-broken cases inside a table.
6. **Approx for floats:** `assert result == pytest.approx(0.3)` - never `==` on floats.
7. **Monkeypatch and mock at boundaries:** the `monkeypatch` fixture (auto-undone) over hand-rolled patching; `mocker` (pytest-mock) over raw `unittest.mock` decorator stacks; patch where the name is *looked up* (`app.service.requests`), not where it's defined - the eternal `mock.patch` trap. Prefer injecting fakes over patching your own internals.
8. **Markers are registered and used:** `slow`, `integration` etc. declared in config (unknown markers should be errors - `--strict-markers`), so `-m "not slow"` gives a fast local loop; `skipif` with reasons, `xfail` (with `strict=True` where fixing is expected) over commenting tests out.
9. **Test behavior, isolate the environment:** `tmp_path` for filesystem (never write to the repo/cwd), `monkeypatch.setenv`/`delenv` for env vars, freeze time (freezegun/`time-machine`) for date logic, seed randomness - a test touching real global state is a flake seed.
10. **Async tests via the project's plugin** (`pytest-asyncio`/anyio): mode configured once (`asyncio_mode = auto` or explicit markers) - an unawaited async test silently passes as a coroutine object in misconfigured suites; verify async tests can actually fail.
11. **Structure and hygiene:** `tests/` mirroring the package layout, test files self-contained enough to read alone, factories (factory_boy/hand-rolled builders) over mega-fixtures for domain objects, `-x --lf` workflow for iteration, and coverage (`pytest-cov`) measured on the paths that matter rather than chased as a percentage.
12. **Database tests:** transaction-rollback isolation per test (or truncate between), real engine over SQLite-standing-in-for-Postgres when SQL dialect matters (Testcontainers where the project supports it), `pytest-django`/framework plugins' fixtures rather than hand-managed connections.
