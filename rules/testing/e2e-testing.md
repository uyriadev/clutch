# E2E Testing - Playwright & Cypress

1. **E2E tests cover critical user journeys, not everything:** signup, login, checkout, the money paths - a handful of high-value flows. Logic edge cases belong in unit tests; an E2E suite trying to be exhaustive becomes a flaky hour-long CI tax nobody trusts.
2. **Selectors by user-visible semantics:** role and accessible name first (`getByRole('button', { name: 'Save' })`), then label/text, `data-testid` as deliberate fallback for semantically-anonymous nodes - never CSS classes or DOM paths (they're styling, they churn). This doubles as an accessibility audit: if you can't select it by role, users of assistive tech can't find it either.
3. **No sleeps, ever.** `waitForTimeout(3000)`/`cy.wait(3000)` is the root of both flakiness and slowness. Playwright auto-waits on actions and `expect(locator)` assertions retry - lean on that; wait for conditions (element state, network response, URL) not durations. Cypress: assert on outcomes, alias-and-wait on intercepted requests (`cy.wait('@saveUser')`), never on time.
4. **Tests are independent and parallel-safe:** each test creates (or API-seeds) its own data, owns its own user/tenant where feasible, and never depends on another test having run. Serial-mode chains of dependent tests fail as a unit and can't shard.
5. **Setup through the fast door:** authenticate once and reuse storage state (Playwright `storageState` / Cypress session), seed data via API or DB calls - not by clicking through the UI in every test. The UI path is the *subject* of a test exactly once; everywhere else it's overhead.
6. **Isolate from third parties:** mock external services (payments, maps, analytics) at the network layer (`page.route`, `cy.intercept`) - your E2E suite tests *your* app, and Stripe's sandbox being slow shouldn't fail your deploy. The app's own backend stays real; that's the point of E2E.
7. **Assert user-observable outcomes:** the success toast, the redirected URL, the row in the table - plus, where it matters, the durable truth (API/DB check) - not internal state. Verify the *absence* states too: error messages on bad input, empty states, permission denials.
8. **Flake policy is zero-tolerance:** a flaky E2E test gets fixed or quarantined the day it flakes - retries (Playwright `retries`, Cypress retries) are a diagnostic cushion, not a lifestyle; a suite that "passes on retry" trains everyone to ignore red.
9. **Debuggability is built in:** trace/video/screenshot on failure (Playwright traces are the gold standard - turn them on for CI retries), meaningful test names, steps (`test.step`) for long flows - an unreproducible CI failure with no artifacts is a total loss.
10. **Run against reality:** production-like build (not dev server quirks), representative viewport(s), seeded-but-realistic data volumes; cross-browser per actual user base (Playwright projects) rather than Chrome-only by default.
11. **Page objects / fixtures in moderation:** extract shared flows (login, navigation) and component interactions into helpers/fixtures; but keep assertions in tests, not buried in page objects - a test should read as its scenario.
12. **Accessibility checks ride along cheaply:** an axe scan (axe-playwright/cypress-axe) on key pages inside existing tests catches regressions the selectors rule already started preventing.
