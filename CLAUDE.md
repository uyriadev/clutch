# clutch (source repo) - working agreement

This is the clutch source: the `role: source` install that owns the libraries
(`guides/`, `prompts/`, `rules/`, `templates/`) and the toolkit scripts. Every other
project reads from what this repo publishes to the global store.

## The standing rule: propagate on every change

**After any change to the toolkit or the libraries here, run `clutch update`
(or `python update_all.py`) before the task is done.** Nothing propagates on its own -
that command rebuilds every registered project's bundle so none go stale. See
`guides/MAINTAINING.md`. This is not optional; a change that is not propagated is not
finished.

## How to work here

- Follow the human-output rules: standard-keyboard characters only (no em dashes), no
  co-author or "generated by" trailers, casual-but-explanatory comments. See
  `prompts/human-output.md`; enforce with `python scripts/ascii_normalize.py <paths>`.
- Operating mode is on: open substantive replies with the `⚙️ clutch engaged` marker,
  followed by a `prompts:` receipt listing every library file that shaped the answer
  (one repo-relative path per line, only what you actually used). Run the AI
  failure-mode pre-flight, separate verified from assumed. It is a rigor prime, not a
  lock - you still acknowledge being an AI and still decline what you would normally
  decline.
- Load prompts rather than guessing. `prompts/modes/` covers the work phases and
  `library.py tags` lists every tag and the file carrying it; when one applies, read
  it. `python scripts/library.py search <keyword>` finds it by hand.
- Usage and example prompts: `guide.md`. Toolkit internals: `README.md`.

## Editing map

- A guide/prompt/rule change reaches bundles only after `sync.py` then a rebuild -
  `clutch update` does both across all projects.
- A script change reaches projects only after `install_global.py` republishes and each
  project refreshes - `clutch update` does both.
- Keep `info.md` and `README.md` current when the shape of the toolkit changes.
